# PHASE 4 — 출고 처리 + 모니터링

> **목표**: `Confirmed` 주문을 출고하고, 전체 시스템 현황을 한눈에 파악할 수 있는 모니터링 기능을 완성한다. 이 Phase가 끝나면 주문 접수부터 출고 완료까지 전체 흐름이 막힘 없이 동작한다.

---

## 구현 범위

### 1. 추가되는 파일

```

├── ReleaseView.h / .cpp

```

### 2. 출고 처리 기능

**대상**: `Confirmed` 상태의 주문

**처리 흐름**:
1. `Confirmed` 주문 목록 표시 (주문번호, 고객명, 시료명, 수량)
2. 담당자가 출고할 번호 선택
3. 상태 전환: `Confirmed` → `Release`
4. 출고 일시 기록 (OrderData에 `releasedAt` 필드 추가)
5. 결과 출력 후 `orders.json` 저장

```cpp
// OrderData에 추가
std::string releasedAt;   // "2026-06-12 11:30:00", 미출고 시 ""
```

### 3. 모니터링 기능

#### 3-1. 주문량 확인

- 상태별 주문 건수 표시: `Reserved` / `Producing` / `Confirmed` / `Release`
- `Rejected`는 집계에서 제외

#### 3-2. 재고량 확인

- 시료별 현재 재고 수량 표시
- 재고 상태 판정:

| 상태 | 조건 | 표시 색상 |
|------|------|---------|
| 여유 | 주문 대비 재고 충분 | 초록 |
| 부족 | 주문 대비 재고 수량 부족 | 노랑 |
| 고갈 | 재고 == 0 | 빨강 |

> **주문 대비 재고 판정 기준**: 해당 시료에 대한 `Reserved` + `Confirmed` 상태 주문의 총 수량 합계와 현재 재고를 비교

### 4. 메인 메뉴 요약 정보 완성

```
 등록 시료   12 종      총 재고    2,840 ea
 전체 주문   36 건      생산라인     3 건 대기
```

### 5. 메인 메뉴 최종 구성

```
[1] 시료 관리
[2] 시료 주문
[3] 주문 승인/거절
[4] 생산라인 조회
[5] 모니터링
[6] 출고 처리
[0] 종료
```

## 완료 조건 (Definition of Done)

- [ ] `Confirmed` 주문 목록이 출고 처리 화면에 출력된다
- [ ] 출고 처리 후 상태가 `Release`로 전환되고 출고 일시가 기록된다
- [ ] 모니터링 주문량 확인에서 상태별 건수가 정확히 집계된다 (`Rejected` 제외 확인)
- [ ] 모니터링 재고량 확인에서 여유/부족/고갈 상태가 올바르게 표시된다
- [ ] 메인 메뉴 진입 시 등록 시료 수·총 재고·전체 주문 수·생산라인 대기 수가 출력된다
- [ ] 주문 접수 → 승인 → (생산) → 출고까지 전체 흐름이 끊기지 않고 동작한다

## 고객님 테스트 시나리오

> 이 Phase의 핵심은 **전체 주문 흐름 완주**입니다. 처음부터 끝까지 한 사이클을 돌려보세요.

**전체 흐름 시나리오**

```
1. 시료 등록 (없으면 Phase 1 데이터 활용)
2. 주문 접수 (재고 충분 케이스 + 재고 부족 케이스 각 1건씩)
3. 주문 승인
   - 재고 충분 → Confirmed 확인
   - 재고 부족 → Producing + 생산라인 등록 확인
4. 생산 완료 처리 → Producing → Confirmed 확인
5. 출고 처리 → Confirmed → Release 확인
6. 모니터링 확인
   - 주문량: 상태별 건수가 맞는지
   - 재고량: 여유/부족/고갈 표시가 직관적인지
7. 메인 메뉴 요약 정보가 현재 상태와 일치하는지
```

**추가 확인 포인트**

- `Confirmed` 주문이 없을 때 출고 처리 메뉴 → "출고 가능한 주문이 없습니다" 안내
- 모니터링에서 `Rejected` 주문이 집계에 포함되지 않는지
- 재고가 0인 시료의 상태가 `고갈`로 표시되는지
