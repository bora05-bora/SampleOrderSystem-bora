# PHASE 2 — 주문 접수 + 승인/거절

> **목표**: 고객 주문을 접수하고, 재고 상황에 따라 승인·거절을 처리할 수 있는 기능을 완성한다.

---

## 구현 범위

### 1. 추가되는 파일

```
src/
├── OrderController.h / .cpp   # 주문 비즈니스 로직
├── OrderView.h / .cpp         # 주문 관련 화면 출력·입력
```

`DataStore`에 orders 관련 CRUD 추가 (`data/orders.json` 신규 생성)

### 2. 데이터 모델 추가

```cpp
enum class OrderStatus { Reserved, Rejected, Producing, Confirmed, Release };

struct OrderData {
    int id;                    // 내부 식별자 (자동 증가)
    std::string orderNo;       // "ORD-20260612-0001"
    std::string sampleId;      // SampleData.id 참조
    std::string sampleName;    // 조회 편의를 위해 비정규화 저장
    std::string customer;      // 고객명
    int quantity;              // 주문 수량
    OrderStatus status;
    std::string date;          // "YYYY-MM-DD"
    // toJson(), fromJson()
};
```

### 3. orders.json 스키마

```json
{
  "nextId": 2,
  "orders": [

      "id": 1,
      "orderNo": "ORD-20260612-0001",

      "customer": "삼성전자 파운드리",
      "quantity": 200,

```

### 4. 주문번호 생성 규칙

```
ORD-{YYYYMMDD}-{4자리 순번}
예) ORD-20260612-0001
```

### 5. 시료 주문 (접수) 기능

- 입력: 시료 ID → 고객명 → 주문 수량
- 입력 내용 확인 화면 출력 후 Y/N 최종 확인
- 확인 시: 주문 생성, 상태 `Reserved`, 주문번호 출력
- 취소(N) 시: 주문 생성하지 않고 메뉴로 복귀
- 제약: 등록되지 않은 시료 ID 입력 시 오류 안내

### 6. 주문 승인/거절 기능

**RESERVED 목록 표시** → 주문번호, 고객명, 시료명, 수량, 상태

**승인 처리 (재고 자동 분기)**

```
재고(stock) >= 주문 수량(quantity)
  → stock -= quantity
  → 상태: Reserved → Confirmed

재고(stock) < 주문 수량(quantity)
  → 상태: Reserved → Producing
  → (생산라인 큐 등록은 Phase 3에서 구현)
  → 이 Phase에서는 상태만 Producing으로 전환
```

**거절 처리**

```
상태: Reserved → Rejected
```

### 7. 메인 메뉴 업데이트

```
[1] 시료 관리
[2] 시료 주문
[3] 주문 승인/거절
[0] 종료
```

---

## 완료 조건 (Definition of Done)

- [ ] 주문 접수 시 주문번호가 자동 발급되고 `Reserved` 상태로 저장된다
- [ ] 재고 충분한 시료 승인 → `Confirmed` 전환, 재고 차감이 반영된다
- [ ] 재고 부족한 시료 승인 → `Producing` 전환된다 (생산은 Phase 3)
- [ ] 거절 → `Rejected` 전환, 이후 승인 목록에서 노출되지 않는다
- [ ] 등록되지 않은 시료 ID로 주문 시 오류 안내가 출력된다
- [ ] 프로그램 재시작 후 주문 상태가 그대로 유지된다
- [ ] RESERVED 목록이 비어있을 때 "처리 대기 중인 주문이 없습니다" 안내가 출력된다

## 고객님 테스트 시나리오

> Phase 1에서 등록한 시료들이 있는 상태에서 시작합니다.

**Step 1 — 재고 충분 케이스**
- S-001(실리콘 웨이퍼, 재고 480ea)로 100ea 주문 접수 → 승인
- 결과: `Confirmed` 전환, 재고 480 → 380 확인

**Step 2 — 재고 부족 케이스**
- S-003(SiC 파워기판, 재고 0ea)로 200ea 주문 접수 → 승인
- 결과: `Producing` 전환, 재고 변화 없음 확인

**Step 3 — 거절 케이스**
- 아무 시료로 주문 접수 → 거절
- 결과: `Rejected` 전환, 승인 목록에서 사라짐 확인

**Step 4 — 잘못된 시료 ID**
- 존재하지 않는 시료 ID(예: S-999) 입력
- 결과: 오류 안내 출력, 프로그램 종료 안됨 확인

**Step 5 — 재시작 후 상태 유지**
- 프로그램 종료 후 재실행 → 모든 주문 상태가 그대로인지 확인
