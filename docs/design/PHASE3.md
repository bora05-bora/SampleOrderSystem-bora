# PHASE 3 — 생산라인

> **목표**: 재고 부족으로 `Producing` 상태가 된 주문을 생산라인 큐에 등록하고, 생산 완료 처리까지 수행할 수 있는 기능을 완성한다.

---

## 구현 범위

### 1. 추가되는 파일

```
src/
├── ProductionLine.h / .cpp    # 생산라인 큐 및 생산 처리 로직
├── ProductionController.h / .cpp
├── ProductionView.h / .cpp
```

### 2. 생산라인 데이터 모델

```cpp
struct ProductionJob {
    int orderId;               // OrderData.id 참조
    std::string orderNo;       // 표시용
    std::string sampleId;
    std::string sampleName;
    int shortage;              // 부족분 = 주문 수량 - 승인 시점 재고
    int actualQty;             // 실 생산량 = ceil(shortage / (yield * 0.9))
    double totalTime;          // 총 생산시간 = productionTime * actualQty
    std::string enqueuedAt;    // 큐 등록 시각
};
```

### 3. 생산라인 JSON 스키마

```json
{
  "queue": [
    {
      "orderId": 1,
      "orderNo": "ORD-20260612-0001",
      "sampleId": "S-003",
      "sampleName": "SiC 파워기판-6인치",
      "shortage": 170,
      "actualQty": 206,
      "totalTime": 164.8,
      "enqueuedAt": "2026-06-12 10:15:00"
    }
  ]
}
```

### 4. 실 생산량 계산

```
부족분     = 주문 수량 - 승인 시점 재고
실 생산량  = ceil(부족분 / (수율 × 0.9))
총 생산시간 = 평균 생산시간 × 실 생산량
```

**계산 예시**

| 항목 | 값 |
|------|-----|
| 주문 수량 | 200 ea |
| 현재 재고 | 30 ea |
| 부족분 | 170 ea |
| 수율 | 0.92 |
| 실 생산량 | ceil(170 / (0.92 × 0.9)) = ceil(205.3) = **206 ea** |
| 평균 생산시간 | 0.8 min/ea |
| 총 생산시간 | 0.8 × 206 = **164.8 min** |

### 5. Phase 2 승인 로직 연결

Phase 2에서 `Producing`으로 전환될 때:
1. 부족분 / 실 생산량 / 총 생산시간 계산
2. `ProductionJob` 생성 후 FIFO 큐 말단에 추가
3. `data/production.json` 에 저장

### 6. 생산라인 조회 화면

- 현재 처리 중인 주문 (큐의 front) 상세 정보
- 대기 중인 주문 목록 (FIFO 순서, 예상 완료 시각 포함)
- 큐가 비어 있을 때 "현재 생산 중인 작업이 없습니다" 안내

### 7. 생산 완료 처리 (수동 트리거)

> 실제 공장 시간을 시뮬레이션하지 않으므로, 담당자가 메뉴에서 "생산 완료" 액션을 선택하면 처리됩니다.

처리 순서:
1. 큐 front의 `ProductionJob` 꺼내기
2. 해당 시료 재고에 `actualQty` 추가
3. 연결된 주문 상태: `Producing` → `Confirmed`
4. `production.json`, `orders.json`, `samples.json` 저장
5. 큐에 다음 작업이 있으면 안내 출력

### 8. 메인 메뉴 업데이트

```
[1] 시료 관리
[2] 시료 주문
[3] 주문 승인/거절
[4] 생산라인 조회
[0] 종료
```

---

## 완료 조건 (Definition of Done)

- [ ] 재고 부족 주문 승인 시 `ProductionJob`이 큐에 자동 등록된다
- [ ] 실 생산량이 `ceil(부족분 / (수율 × 0.9))` 공식대로 계산된다
- [ ] 생산라인 조회 시 처리 중 + 대기 목록이 FIFO 순으로 출력된다
- [ ] 여러 건 승인 시 큐에 FIFO 순으로 쌓인다
- [ ] 생산 완료 처리 후 재고가 `actualQty`만큼 증가한다
- [ ] 생산 완료 처리 후 해당 주문 상태가 `Confirmed`로 전환된다
- [ ] 큐의 다음 작업이 있으면 이어서 조회 가능하다
- [ ] 프로그램 재시작 후 생산 큐 상태가 유지된다

## 고객님 테스트 시나리오

> Phase 2에서 `Producing` 상태 주문이 최소 1건 이상 있는 상태에서 시작합니다.

**Step 1 — 생산라인 조회**
- 메뉴 [4] 진입 → 현재 처리 중인 주문 정보가 보이는지 확인
- 실 생산량이 공식에 맞는지 직접 계산과 비교

**Step 2 — 복수 주문 큐 쌓기**
- 재고 부족 주문을 2~3건 더 승인
- 생산라인 조회 → FIFO 순으로 대기 목록에 쌓이는지 확인

**Step 3 — 생산 완료 처리**
- `[1] 생산 완료 처리` 선택
- 결과 확인:
  - 해당 시료 재고가 실 생산량만큼 늘었는지
  - 해당 주문 상태가 `Confirmed`로 바뀌었는지
  - 다음 대기 작업이 "현재 처리 중"으로 올라왔는지

**Step 4 — 재고 0 케이스**
- 재고가 0인 시료 주문 승인 → 부족분 = 주문 수량 전체 → 실 생산량 계산 확인

**Step 5 — 재시작 후 큐 유지**
- 프로그램 종료 후 재실행 → 생산 큐 대기 목록이 그대로인지 확인
