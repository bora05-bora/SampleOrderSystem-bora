### 2. 생산라인 상태 정의

생산라인은 단일 라인(Single Line)이며 FIFO 방식으로 동작한다.

| 상태 | 조건 | 동작 |
|------|------|------|
| **EMPTY** | 큐에 작업 없음 | 주문이 들어오는 즉시 생산 시작 (`startedAt` 기록) |
| **RUNNING** | 작업 처리 중 | 신규 주문은 대기 큐 말단에 추가 |

- 큐의 **front** 항목이 현재 처리 중인 작업이다.
- 현재 작업이 완료되면 큐에서 제거하고, 다음 항목이 있으면 자동으로 `startedAt`을 기록하며 생산 시작.

---

### 3. 생산라인 데이터 모델

```cpp
struct ProductionJob {
    int orderId;               // OrderData.id 참조
    std::string orderNo;       // 표시용 주문번호
    std::string sampleId;
    std::string sampleName;
    int quantity;              // 주문 수량
    int stock;                 // 승인 시점 재고
    int shortage;              // 부족분 = quantity - stock
    int actualQty;             // 실 생산량 = ceil(shortage / (yield × 0.9))
    double totalTime;          // 총 생산시간 (분) = productionTime × actualQty
    std::string enqueuedAt;    // 큐 등록 시각 (YYYY-MM-DD HH:MM:SS)
    std::string startedAt;     // 생산 시작 시각 (front 항목에만 유효)
};
```

- 라인 상태가 EMPTY일 때 주문이 추가되면 즉시 `startedAt`을 기록.

### 5. 실 생산량 계산

```
부족분      = 주문 수량 - 승인 시점 재고
실 생산량   = ceil(부족분 / (수율 × 0.9))
총 생산시간 = 평균 생산시간(min/ea) × 실 생산량   [단위: 분]
```

**계산 예시**

| 항목 | 값 |
|------|-----|
| 주문 수량 | 200 ea |
| 현재 재고 | 30 ea |
| 부족분 | 170 ea |
| 수율 | 0.92 |
| 실 생산량 | ceil(170 / (0.92 × 0.9)) = ceil(205.3) = **206 ea** |
| 평균 생산시간 | 0.8 min/ea |
| 총 생산시간 | 0.8 × 206 = **164.8 min** |

### 6. Phase 2 승인 로직 연결

Phase 2에서 `PRODUCING`으로 전환될 때:

1. 부족분 / 실 생산량 / 총 생산시간 계산
2. `ProductionJob` 생성 → 큐 말단에 추가 (`enqueuedAt` 기록)
3. 생산라인이 **EMPTY** 상태이면 즉시 `startedAt` 기록 (생산 시작)
4. `data/production.json` 저장

### 7. 실시간 진행도 처리

생산라인 조회 화면 진입 시:

1. 현재 시각과 `startedAt`의 차이(경과 시간)를 계산
2. `진행도(%) = 경과 시간 / totalTime × 100` (100% 초과 시 100% 고정)
3. `완료 예정 시각 = startedAt + totalTime`
4. **진행도가 100%에 도달한 경우 자동으로 완료 처리** 후 화면 갱신:
   - 큐 front 제거
   - 시료 재고에 `actualQty` 추가
   - 주문 상태: `PRODUCING` → `CONFIRMED`
   - 다음 항목이 있으면 `startedAt` 기록 (즉시 생산 시작)
   - `production.json`, `orders.json`, `samples.json` 저장

대기 항목의 **예상 완료 시각**:

```
대기 1번 예상 완료 = 현재 처리 중 완료 예정 시각 + 대기 1번 totalTime
대기 2번 예상 완료 = 대기 1번 예상 완료 시각    + 대기 2번 totalTime
...
```

## 완료 조건 (Definition of Done)

- [ ] 재고 부족 주문 승인 시 `ProductionJob`이 큐에 자동 등록된다
- [ ] 생산라인이 EMPTY 상태일 때 주문 등록 즉시 `startedAt`이 기록된다
- [ ] 실 생산량이 `ceil(부족분 / (수율 × 0.9))` 공식대로 계산된다
- [ ] 생산라인 조회 시 진행도(%)와 progress bar가 경과 시간 기반으로 출력된다
- [ ] 생산라인 조회 시 완료 예정 시각이 올바르게 표시된다
- [ ] 대기 목록에서 각 항목의 예상 완료 시각이 누적 계산된다
- [ ] 진행도 100% 도달 시 자동으로 완료 처리된다 (재고 증가 + CONFIRMED 전환)
- [ ] 완료 후 다음 대기 작업이 즉시 생산 시작(`startedAt` 기록)된다
- [ ] 여러 건 승인 시 큐에 FIFO 순으로 쌓인다

## 고객님 테스트 시나리오

> Phase 2에서 `PRODUCING` 상태 주문이 최소 1건 이상 있는 상태에서 시작합니다.

**Step 1 — EMPTY → RUNNING 전환 확인**
- 재고 부족 주문 승인 → 생산라인 조회 → 상태가 RUNNING이며 `startedAt`이 승인 시각인지 확인

**Step 2 — 진행도 확인**
- 메뉴 [4] 진입 → 진행도(%)와 progress bar가 경과 시간에 맞게 표시되는지 확인
- 완료 예정 시각이 `startedAt + totalTime`과 일치하는지 직접 계산과 비교

**Step 3 — 복수 주문 FIFO 확인**
- 재고 부족 주문을 2~3건 더 승인
- 생산라인 조회 → FIFO 순으로 대기 목록에 쌓이는지 확인
- 대기 항목의 예상 완료 시각이 누적 계산되는지 확인

**Step 4 — 자동 완료 처리 확인**
- 테스트용으로 짧은 `totalTime` 시료를 사용하거나 `startedAt`을 과거 시각으로 직접 수정
- 생산라인 조회 진입 시 완료 감지 메시지 출력 확인
- 해당 시료 재고가 `actualQty`만큼 증가했는지 확인
- 해당 주문 상태가 `CONFIRMED`로 변경되었는지 확인
- 다음 대기 작업이 "현재 처리 중"으로 올라오고 `startedAt`이 갱신되었는지 확인

**Step 5 — 재고 0 케이스**
- 재고가 0인 시료 주문 승인 → 부족분 = 주문 수량 전체 → 실 생산량 계산 확인

**Step 6 — 재시작 후 큐 유지**
- 프로그램 종료 후 재실행 → `startedAt` 포함 생산 큐 상태가 그대로인지 확인
- 재실행 후 생산라인 조회 시 경과 시간이 올바르게 이어서 계산되는지 확인
