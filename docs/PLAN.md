# PLAN — 반도체 시료 생산주문관리 시스템 개발 계획

> 각 Phase는 **실제로 실행되고 동작하는 소프트웨어**를 목표로 합니다.
> Phase가 끝날 때마다 고객님께서 직접 실행해 보시고 피드백을 주시면 다음 Phase에 반영합니다.

---

## 전체 Phase 요약

| Phase | 핵심 목표 | 고객님이 확인할 수 있는 것 |
|-------|---------|------------------------|
| Phase 1 | 프로젝트 뼈대 + 시료 등록·조회 | 시료를 등록하고 목록을 확인할 수 있는가 |
| Phase 2 | 주문 접수 + 승인/거절 | 주문을 넣고 승인·거절이 정확히 처리되는가 |
| Phase 3 | 생산라인 | 재고 부족 시 생산이 올바르게 큐에 쌓이고 처리되는가 |
| Phase 4 | 출고 처리 + 모니터링 | 전체 주문 흐름이 끊기지 않고 완주되는가 |
| Phase 5 | 품질 완성 | 잘못된 입력, 극단적 상황에서도 안정적으로 동작하는가 |

---

## Phase 1 — 프로젝트 기반 구축 + 시료 관리

### 개발 목표

- Visual Studio 솔루션 및 프로젝트 파일 생성 (MVC 디렉토리 구조)
- JSON 파일 기반 데이터 영속화 (`data/samples.json`)
- 메인 메뉴 화면 출력 (시스템 현황 요약 포함)
- **시료 관리** 기능 완성
  - 시료 등록 (ID, 이름, 평균 생산시간, 수율)
  - 시료 목록 조회 (재고 포함)
  - 시료 이름 검색

### 고객님께서 확인해 주실 부분

> **시나리오**: 시스템을 처음 실행한 S-Semi 담당자가 되어, 취급하는 반도체 시료들을 등록해 보세요.

1. **프로그램 실행** → 메인 메뉴가 깔끔하게 나오는지
2. **시료 등록** → 시료 ID, 이름, 평균 생산시간, 수율을 입력하면 오류 없이 등록되는지
3. **시료 목록 조회** → 등록한 시료들이 재고 수량과 함께 표 형태로 보이는지
4. **시료 검색** → 이름의 일부만 입력해도 찾아지는지
5. **재시작 후 데이터 유지** → 프로그램을 껐다가 다시 켜도 등록한 시료가 남아 있는지

## Phase 2 — 주문 접수 + 승인/거절

### 개발 목표

- JSON 파일 기반 주문 데이터 영속화 (`data/orders.json`)
- **시료 주문(접수)** 기능
  - 시료 ID, 고객명, 주문 수량 입력
  - 주문번호 자동 발급
  - 초기 상태: `RESERVED`
- **주문 승인/거절** 기능
  - RESERVED 주문 목록 표시
  - 승인 시 재고 자동 확인 후 상태 분기
    - 재고 충분 → `CONFIRMED` 즉시 전환
    - 재고 부족 → `PRODUCING` 전환 (생산라인 등록은 Phase 3)
  - 거절 시 → `REJECTED` 즉시 전환

### 고객님께서 확인해 주실 부분

> **시나리오**: Phase 1에서 등록한 시료에 대해 고객사 주문이 들어왔습니다. 주문을 접수하고 처리해 보세요.

1. **주문 접수** → 시료 ID·고객명·수량을 입력하면 주문번호가 발급되고 RESERVED 상태가 되는지
2. **승인 — 재고 충분 케이스** → 재고가 넉넉한 시료를 주문했을 때 바로 CONFIRMED가 되는지
3. **승인 — 재고 부족 케이스** → 재고가 부족한 시료를 주문했을 때 PRODUCING으로 바뀌는지
4. **거절** → REJECTED로 전환되고 이후 목록에서 사라지는지
5. **재시작 후 주문 유지** → 껐다가 켜도 주문 상태가 그대로인지
6. **없는 시료로 주문 시도** → 등록되지 않은 시료 ID를 입력하면 오류 안내가 나오는지

## Phase 3 — 생산라인

### 개발 목표

- 생산라인 큐 자료구조 구현 (FIFO)
- Phase 2의 "재고 부족 → PRODUCING" 연결: 승인 시 생산라인 큐에 자동 등록
- 생산 수량 계산 로직
  - `부족분 = 주문 수량 - 현재 재고`
  - `실 생산량 = ceil(부족분 / (수율 × 0.9))`
  - `총 생산시간 = 평균 생산시간 × 실 생산량`
- **생산라인 조회** 화면
  - 현재 처리 중인 주문 정보 (주문번호, 시료, 실 생산량, 예상 완료 시각)
  - 대기 중인 주문 목록 (FIFO 순, 예상 완료 시각 포함)
- 생산 완료 처리 (메뉴 액션으로 수동 트리거)
  - 재고에 생산량 반영
  - 주문 상태: `PRODUCING` → `CONFIRMED`

### 고객님께서 확인해 주실 부분

> **시나리오**: 재고가 부족한 주문 여러 건을 연달아 승인해 보세요. 생산라인이 올바르게 작동하는지 확인합니다.

1. **생산라인 조회** → 현재 생산 중인 항목과 대기 목록이 FIFO 순으로 보이는지
2. **생산량 계산 정확성** → 부족분, 실 생산량, 예상 생산시간이 공식에 맞게 계산되는지
   - 예: 주문 200ea, 재고 30ea, 수율 0.92 → 부족분 170ea, 실 생산량 206ea
3. **생산 완료 처리** → 완료 후 재고가 늘어나고, 주문 상태가 CONFIRMED로 바뀌는지
4. **다음 대기 주문 자동 시작** → 첫 번째 완료 후 두 번째 주문이 생산 중 상태가 되는지
5. **재고 0인 시료 주문** → 재고가 아예 없는 경우에도 정확히 생산량이 계산되는지

## Phase 4 — 출고 처리 + 모니터링

### 개발 목표

- **출고 처리** 기능
  - CONFIRMED 주문 목록 표시
  - 선택한 주문 출고 실행: `CONFIRMED` → `RELEASE`
  - 출고 일시 기록 및 결과 출력
- **모니터링** 기능
  - 주문량 확인: 상태별(RESERVED / PRODUCING / CONFIRMED / RELEASE) 건수
  - 재고량 확인: 시료별 재고 수량 + 상태(여유 / 부족 / 고갈)
- 메인 메뉴 요약 정보 완성
  - 등록 시료 수, 총 재고, 전체 주문 수, 생산라인 대기 수

### 고객님께서 확인해 주실 부분

> **시나리오**: 전체 주문 흐름을 처음부터 끝까지 완주해 보세요. 주문 접수 → 승인 → (생산) → 출고까지 한 사이클을 돌려봅니다.

1. **출고 처리** → CONFIRMED 주문을 선택해 출고하면 RELEASE로 바뀌는지
2. **모니터링 — 주문량** → 각 상태별 건수가 실제와 일치하는지 (REJECTED는 빠져 있어야 함)
3. **모니터링 — 재고량** → 여유/부족/고갈 상태가 직관적으로 표시되는지
4. **메인 메뉴 요약** → 화면 진입 시 시스템 현황이 한눈에 들어오는지
5. **전체 흐름 완주** → 주문 접수부터 출고 완료까지 막히는 단계 없이 진행되는지

---

## Phase 5 — 품질 완성 (안정성 · 사용성)

### 개발 목표

- 잘못된 입력 처리 (숫자 입력란에 문자, 범위 초과, 빈 입력 등)
- 경계값 처리 (재고 정확히 0, 주문 수량과 재고가 동일한 경우 등)
- 화면 구성 통일 (구분선, 컬러, 정렬 일관성)
- 전체 시나리오 기반 최종 검수

### 고객님께서 확인해 주실 부분

> **시나리오**: 일부러 잘못된 값을 넣어 시스템을 흔들어 보세요.

1. **잘못된 입력** → 수량에 음수·문자·공백을 넣어도 프로그램이 죽지 않고 안내 메시지가 나오는지
2. **존재하지 않는 ID** → 없는 시료 ID나 주문번호를 입력하면 적절한 안내가 나오는지
3. **빈 목록 상태** → 주문이 하나도 없을 때 승인/출고 메뉴에 들어가면 빈 상태 안내가 나오는지
4. **연속 사용 피로도** → 여러 기능을 빠르게 반복해서 사용해도 데이터가 꼬이지 않는지
5. **전반적인 화면 완성도** → 글자 정렬, 구분선, 상태 표시 색상이 일관되고 읽기 편한지
